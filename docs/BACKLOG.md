## 1. 导航方向反了：课 → 内容，应该是内容 → 课

**状态**：已确认，用户明确要求"以后再改"，先记着。

写作题和单词都被当成"某一课的附属物"，只能先选课才能访问。但一道作文题、一个单词，
本身就是独立实体，课只是它的一个属性。

**实测**：

- 写作是**真被锁死**的。`app.py` 的 `_writing_task_summaries()` 里有一行
  `if lesson == "全部": return []` ——写作压根没有"全部"入口。
- 背单词**其实没锁**。`lesson_options = ["全部"] + sorted(LESSONS)`，
  `start_lesson_round()` 认 `"全部"`；数据层 (`lessons` / `zh_by_lesson` /
  `provenance_by_lesson`) 一直支持一词多课，1251 个词里 290 个跨多课。
  所以**背单词这边不需要架构改造**，只欠一个小功能：从搜到的某个词直接开练。

**改法**（约 60 行，风险低——契约层 `WritingTask.lesson` 本来就有，不用改数据）：

1. `JsonWritingContent` 加 `list_all_tasks()`，glob `L*/writing_tasks.json`

4. 侧栏「✍️ 写作练习」在「全部」下也可点，下拉标签带课号
5. 顶层加一个与「学习」平级的写作入口

**不要**为了赶时间把题硬塞进当前课——那是一次性代码，之后还得拆。

```bash

grep -n scope writing/content.py   # 只在解析时读一次，之后再没人用
```

后果：L33-W1 的 49 条素材里，**25 条标着 `task_type` 或 `general`**（共 9,854 字符），

## 3. 组装线有三格是空的，两条素材只在「详解」里可见

**状态**：已确认，等用户体验后决定。

`writing_skeletons.json` 的 `tache_2` 有 7 步，但 L34-W2 的素材只填了 4 步：

```
pick_scenario   0 条        use_template   0 条        final_check   0 条
```

而 `L34-W2-traps`（本题最容易错的几处）和 `L34-W2-length`（字数分配与增删顺序）

改的是数据不是代码。但「交卷前检查」那格该放什么，用户自己写作时才知道顺不顺手，
所以没有自作主张。

## 4. 敲法语和念法语是两套相反的判分口径

**状态**：已确认，用户决定**保持现状**（TCF 写作确实扣重音）。记录以备将来改主意。

同一个字符串 `la securité`（漏重音）：

| 判分函数 | 用在 | 返回 | 容错 | 有申诉吗 |
|---|---|---|---|---|
| `check_fr` | 敲法语 | 硬 `bool` | 零容错、重音严格 | ❌ 没有 |
| `check_zh` | 敲中文 | `True/None` | 义项切分、占位符骨架 | ✅ 算我对/算我错 |
| `check_speech` | 念法语 | `True/None` | 去重音 + 编辑距离 + 可省冠词 | ✅ 有 |

`check_speech` 宽到连 `la sekurite` 都判对。同一门语言的两个技能，一个零容错无申诉，
一个宽到几乎判不错。

用户的选择是保持 `check_fr` 硬判错，只把自判按钮改名为「中文算我对／中文算我错」
并写明法语不受其影响。**不要**擅自给 `check_fr` 加容错。

## 6. L34 的阅读证据文件格式该向 L31/L32 看齐

**状态**：已确认，不急。

`L31.T5.reading-evidence.md` 和 `L32.T6.reading-evidence.md` 有明确分节：

```
### Printed source text
### Question and options
### Visible markings
### Handwritten annotations
### Evidence notes
```

这让"这个词到底出现在试卷原文里，还是出现在我自己的分析文字里"**可以机器判定**。

慢且容易漏。写 ingest skill 的下一版时应把分节定成规范。
