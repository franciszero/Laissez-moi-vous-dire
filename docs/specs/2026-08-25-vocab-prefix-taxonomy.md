## 为什么要改

学习者看到的中文义 `zh` 带一个方括号前缀，标明这个词从哪来：

```
[T11Q9] 面谈；（尤指）面试
[L38写作T3] 巩固
[T5Q3 补] 时刻表 [Opus5 建议：TCF 便条题常年考这一组]
```

`matcher._SOURCE_PREFIX` 在判分前把前缀和 `[… 建议：…]` 后缀剥掉，所以前缀不影响判分。
`tests/test_matcher.py::test_every_real_vocab_gloss_strips_clean` 扫全库确保剥离干净。

这套前缀是围着**阅读卷的题号**设计的（`T<test>Q<question>`）。两个问题：

**一、没有卷子就没有锚点。** 课程从阅读转向口语和写作之后，题号不存在了。
L38 因此不得不新造 `[L38口语T1]`／`[L38口语T2]`，
**132 行里 71 行（54%）是口语**，一个题号都挂不上。

**二、前缀是单值的，归属是多值的。** L38 有 40 行 `[L38写作…]` 的词，
老师同时说过这个话题「写作和口语会同时考」——这些词同样属于口语。
前缀强行宣称了唯一归属。

实际已经出现的例子：`se promener` 一个词带两条 provenance，
一条来自写作 T1 的批改（老师圈出你写错的 premène），
一条来自口语 T2 的讲义（他写在公园那条线旁边）。
provenance 装得下，前缀装不下。

## 设计

**两层拆分。**

### 第一层：`zh` 前缀 = 粗粒度技能标签，单值

只有六个取值：

| 取值 | 用于 |
|---|---|
| `[L<n>听写]` | 开课听写／课前复习的词 |
| `[L<n>阅读]` | 阅读卷讲评带出来的词 |
| `[L<n>听力]` | 听力练习讲评带出来的词 |
| `[L<n>写作]` | 写作讲评、范文、万金油表达 |
| `[L<n>口语]` | 口语 T1/T2/T3 对练与讲义 |
| `[L<n>课外]` | 课外题、课后补注等不属于以上任何一项的 |

保留补充档写法 `[L<n>写作 补]`，保留 `[<模型> 建议：…]` 后缀不变。

> **「听力」是预演跑出来才发现的。** 原设计只列了五个取值，
> 是照 L38 一课想当然的；实际库里有 `[L36听力]` 43 行、`[L35听力T2]` 33 行。
> 这条记在这里，是因为它说明**这类分类法必须先扫全库再定，不能从一课外推**。

### 第二层：细粒度来源 = `provenance[].source_ref`

题号、批改轮次、讲义出处全部进 `source_ref`。理由：

- 它**本来就是结构化的**，格式见
  [`2026-07-23-vocab-provenance-schema.md`](2026-07-23-vocab-provenance-schema.md)
- 它**本来就是数组**，一个词可以带多条，天然支持多归属
- 它**本来就在 App 里渲染**——「📚 为什么收录这个词」面板会把每条
  `source_ref` / `selection_reason` / `teacher_action` / `evidence` 都显示出来

一个词同时属于写作和口语，就带两条 provenance：

```json
"provenance": [
  {"source_ref": "L38:writing-T3:autonomie", "teacher_action": "memorize", ...},
  {"source_ref": "L38:oral-T2:mindmap",      "teacher_action": "handout",  ...}
]
```

`zh` 前缀取**老师要求最强的那一次**所在的技能，其余归属只进 provenance。

### 为什么这样切

粗粒度那一层是学习者**扫一眼**要看的（这词是写作词还是听写词，决定先背哪批）；
细粒度那一层是他**点开才看**的（具体哪道题、哪次批改、老师原话）。

现在的问题是把细粒度硬塞进了扫一眼那一层——既装不下，又容易分错。

## 边界

1. `[L<n>听写]` 只给开课听写／课前复习，不给课上任何其它环节报的词。
2. 一个词在多个技能下出现时，前缀取**老师要求最强**的那一次；判不出强弱就取**最早**的一次。
3. **老师要求档永远无后缀。** `补` 只给 agent 或 AI 提出的词。
   老师发了讲义但课上没讲到的，用 `teacher_action: handout` 表达，**不加 `补`**——
   它是老师给的，不是补的（见 `app._PROVENANCE_ACTION_LABELS`）。
4. 前缀形状必须满足 `matcher._SOURCE_PREFIX`（`[L<数字>…]`），
   否则 `check_zh` 会从自动判分**静默退化**成手动自评——不会报错，只会悄悄变差。
   六个取值都满足。

## 迁移阻塞项

`scripts/prefix_migration_dryrun.py` 的实测结果（2026-08-25，只读）：

```
扫描 22 个 vocab.json，共 2164 行，其中 995 行的 zh 会变。
```

**⚠️ 521 行（占全库 24%）的题号只存在于前缀里，provenance 的 `source_ref` 没有对应锚点。**

这些行一旦改前缀，题号信息就永久丢失。**迁移不能在补完这 521 行之前执行。**

按课分布：

| 课 | L29 | L30 | L34 | L35 | L36 | L37 | L38 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 会丢锚点的行 | 112 | 122 | 89 | 71 | 74 | 53 | **0** |

**只有 L38 是干净的**——它的每一行 `source_ref` 都带了锚点。
L29–L37 全部有缺口，所以「只迁移较新的几课」并不能绕开这个问题：
L35–L37 加起来仍有 198 行会丢。

## 还有一个本规范原先没有处理的情况

**全库 2164 行里，1122 行（52%）根本没有前缀。**

| 课 | 无前缀 | 有前缀 |
|---|---:|---:|
| L17–L28、L33 | 1122 | 0 |
| L29 | 39 | 112 |
| L31 | 48 | 69 |
| L32 | 11 | 55 |
| L30、L34–L38 | 0 | 706 |

前缀制度是从 **L29** 才开始的，**L34** 起才稳定全覆盖。
也就是说这个库**早就不是单一制度**了，现在是「无前缀」和「旧前缀」两套并存。

这带来一个必须先回答的问题：**新方案要不要给那 1122 行补前缀？**
如果不补，迁移之后库里会变成三套（无前缀／旧前缀／新前缀）。
本规范倾向于**不补**——那些课的词早已练过多轮，改显示的收益低于风险——
但这需要明确写下来，而不是默认。

原先无法映射的 4 行，2026-08-25 用户已裁定归属并写进映射规则：

| 现有前缀 | 行数 | → | 理由 |
|---|---:|---|---|
| `[L<n>动词变位]` | 3 | `[L<n>听写]` | 变位操练紧接开课听写做，同一个环节 |
| `[L<n>课后补注]` | 1 | `[L<n>课外]` | 不属于任何技能环节 |

这 4 行都在 L35／L37，按路线 C **本轮不动**；规则先落进脚本，供以后需要时用。
现在预演的「无法映射」一栏是 **无 ✅**。
