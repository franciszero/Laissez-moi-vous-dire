# 第 0 部分 · 给 agent 的阅读指引

这一部分专为**带着任务进来的 agent** 写。人类审阅者可以跳到第 1 部分。

## 0.1 三十秒摘要

这个课程知识库覆盖 39 节已转录的课，其中 22 节有词表、19 节有知识点，
合计 737 个知识点、2164 个词条行。它工作，但**没有身份层**：
同一个东西在不同课里被存成互不相识的多份，因此无法跨课比较、合并或去重。

本文档提议在现有数据之上加一层：把**观察**（发生了什么）和**概念**（怎么归类）分开，
概念之间可递归组合，并规定谁有权建立/否决连接。

**它不替换任何现有产物。**`vocab.json`、`manifest.json`、8501 的词汇轮和知识卡照常工作。

## 0.3 硬规则（无论什么任务都不可违反）

1. **不要重跑已完成的抽取。**39 节课的转录、19 节课的 species、22 节课的 vocab 都已生成。
   本设计是**重组**已有数据，不是重新抽取。
2. **不要给 `genus` / `family` / `system` 填新值当身份用。**它们已被证明是装饰性的
   （见 §1.2）。在身份层落地之前，把它们当自由文本，不要基于它们做合并。
3. **不要在概念层做静默合并。**任何把两个东西认定为「同一个」的动作都必须留痕
   （谁提议、依据、可否决）。这条的代价见 §6.1。
4. **不要新增存储层级。**递归已提供无限深度（§2.4）。「再抽象一层」是本设计
   明确拒绝的（§2.5）。
5. **证据不可指向二进制。**provenance 的 `evidence.file` 必须是可当 UTF-8 打开的文本。
   原件（PDF/图片）写进课内证据层 markdown，由它记录路径与 SHA-256。
6. **否决与创建同等重要。**见 §3.4。删除一条连接而不记录理由，等于让下一个 agent
   重新提议一遍。

## 0.4 已决 / 未决（不要重新论证已决项）

**已决**（有数据支撑，见对应节）：

- 沙粒与节点的判定标准是**认识论的**（观察 vs 解释），不是结构性的（出度）——§2.1
- 边必须有类型；对称边允许双向，层级边上的环是 bug——§2.3
- 不加固定层级，用递归——§2.5
- 沙粒层老师权威、概念层使用者权威且留痕——§3
- `tag-vocabulary.json` 是真受控词表，可信；`genus` 不是——§1.2

**未决**（欢迎审阅者攻击，见 §7）：

- 沙粒的粒度到底取 provenance 记录还是更细
- canonical key 的命名规则
- 是否需要独立存储，还是寄生在现有 JSON 里
- 概念层是否要进 8501，还是只服务于分析与手册

# 第 1 部分 · 问题

## 1.1 现状

| 对象 | 规模 | 存放 |
|---|---:|---|
| 已转录的课 | **39**（L0–L38） | — |
| 转录行 | **61,127** | `VibeVoice/docker-data/outputs/L*/L*_final_working.md` |
| 有词表的课 | **22**（L17–L38） | `本地录屏课/L*/vocab.json` |
| 有知识点的课 | **19**（L21–L38 ＋ L9） | `census/recapture/reconciled/L*.species.json` |
| 知识点（reviewed species） | 737 | `VibeVoice/docs/french-wiki/census/recapture/reconciled/L*.species.json` |
| 词条行 | 2,164 | `本地录屏课/L*/vocab.json` |
| provenance 记录 | 963 | 同上，行内数组 |
| 受控标签 | 5 primary_class + 9 facet / 55 tag | `census/tag-vocabulary.json` |

这套东西**是工作的**：每课能生成 manifest，8501 上能刷词和知识卡，SRS 进度稳定，
provenance 可解析、可验证（`verify_launch.py --require-vocab-provenance`）。

**本设计不是因为它坏了，是因为它无法跨课。**

## 1.2 病灶：没有身份层

三组实测数据。

**（a）分类字段是装饰性的**

species 的 schema 设计了 `genus`（属）作为分类身份键。实际：

| 字段 | 有值 | 唯一值 | 跨课重名 |
|---|---:|---:|---:|
| `genus` | 642 / 737 | **638** | **4 组** |
| `family` | 642 / 737 | 596 | — |
| `system` | 737 / 737 | 418 | — |

642 个有值的 `genus` 里 638 个互不相同。19 节课的建卡过程中，每张卡都现编了一个
唯一值，从未把它当共享键用过。**分类字段存在，但不携带信息。**

对比：`tag-vocabulary.json` 是**真受控**的（55 个标签，改动需要编辑词表本身），
因此按标签切片可靠。这证明问题不是「没有词表」，是「身份键没有词表」。

**（b）同一个词被存成互不相识的多份**

2,164 个词条行，只有 **1,607 个不同的 lemma**；**405 个 lemma（25%）跨课重复**。
`se garer` 出现 6 次，`un cadeau` / `rencontrer` / `un séjour` / `un stage` 各 5 次。

`un cadeau` 现在是分散在 5 节课里的 5 个独立行，每一行都同时承担「这个词」
和「这次出现」两个角色。

**（c）因此跨课比较只能靠猜**

因为没有身份，2026-08-26 的聚类只能用 `french_items` 字符串重叠做代理，
产生了可证的坏合并（§6.1）。**算法调参救不了这个——缺的是身份，不是相似度。**

## 1.3 为什么现在做

课程已从阅读转向口语和写作，而教学内容高度跨课复用：**729 个可参与重叠检测的
知识点里，281 组两两跨课重复**，其中 207 个知识点落进 54 个跨课簇（28%）。

> **口径**：全库 737 个 reviewed 知识点，其中 8 个不进重叠检测（5 个 `french_items`
> 为空，3 个只列了裸冠词，被归一化剥成空串——见 §6.1 第 3 条）。281 与 54 都是
> 729 基数上的数，不要挂在 737 上。

同时 `L38 的开课听写 = L37 阅读卷的词表重报`，老师本人就在跨课复用。
没有身份层，这种复用对系统不可见。

还有一个规模上的理由：**39 节课已转录，但只有 19 节进入了知识层**。
在没有身份层的情况下补齐剩下的 20 节，只会把「互不相识的多份」这个问题
按比例放大一倍。先修身份，再补量。

# 第 2 部分 · 数据模型

## 2.1 两类对象，界线是认识论的

| | **观察（沙粒）** | **概念（节点）** |
|---|---|---|
| 断言什么 | 发生过什么 | 怎么归类 |
| 例 | 「L38 `01:09:00`，老师把 `à préparer` 改成 `de se préparer`」 | 「permettre 和 aider 的介词方向相反」 |
| 真假 | 可验证：回放录音、看纸面 | 无真假，只有有用/没用 |
| 被什么推翻 | 更强的证据 | 讨论 |
| 可变性 | **不可变** | **廉价、可改、可并存多套** |
| 谁有权 | 老师（§3.1） | 使用者（§3.2） |

**不要用出度来分。**转录里「这题我们 L37 讲过」这句话指向了别的东西，但它仍是观察；
一个刚命名、还没挂任何东西的概念出度为 0，但它仍是概念。

**实操判据**：问「要推翻它，我该去听录音还是该找人讨论？」

**当前数据里的混淆**：`vocab.json` 的每一行同时是概念和观察。这不是模糊，是存错了。

## 2.2 沙粒的粒度

取 **provenance 记录**（现有 963 条），不是词条行。

每条 provenance 已经是：原子的、带课号与时间戳、指向可解析证据、记录了教学关系。
它天然就是「在某课某时刻，老师对某个词做了某事」。

词条行不是沙粒——它是概念与观察粘在一起的产物，正是病灶本身。

> **未决**：963 条是否足够细？转录窗口（61,127 行）是更细的一层，
> 但它没有语义。见 §7.1。

## 2.3 边必须有类型

只有「归属」一种关系不够。已经需要的至少有：

| 边类型 | 方向性 | 环 | 说明 |
|---|---|---|---|
| `observes` | 概念 → 观察 | — | 一个概念被哪些观察支撑 |
| `groups` | 概念 → 概念 | **环是 bug** | 层级归属，需环检测 |
| `contrasts` | 概念 ↔ 概念 | 必须双向 | `mieux` ↔ `meilleur` |
| `synonym_of` | 概念 ↔ 概念 | 必须双向 | `imitation` ↔ `plagiat` |
| `corrects` | 观察 → 概念 | — | 这次纠错指向哪条规则 |
| `assigns` | 观察 → 概念 | — | 布置的作业指向哪个话题 |

**a↔b 允许与否由边类型决定**，不是洁癖问题：对称边上双向是正确的；
层级边上的环意味着层级塌了，必须检测并报错。

**好消息**：边类型已经存在。`teacher_action` 字段（`memorize` / `correction` /
`contrast` / `synonym` / `word_family` / `review` / `handout` / `agent_supplement` /
`user_supplied`）就是边的类型——只是它现在长在行上，不是长在边上。搬位置即可，
不需要重新设计。

## 2.4 递归

概念可以把概念当作观察来抓。这不是特例，是同一条边（`groups`）的自然结果。

真实例子：

```
「permettre 的论元框架」          ← 概念
   ├─ groups → 「permettre qch」            ← 概念
   ├─ groups → 「permettre à qn de + inf」  ← 概念
   ├─ groups → 「aider qn à + inf」         ← 概念
   └─ observes → L38:01:09:00 的那次批改     ← 观察
```

同一个节点既抓概念又抓观察。**这就是你要的「节点也能把其他节点视作沙粒」。**

## 2.5 不要加固定层级

「n 个节点层之上是不是还能再抽象一层」——**不需要，而且有害。**

`节点 → 节点` 这条边已经给了无限深度。再定义命名的第三层，等于把某一次的
理解固化进存储，会重演 `genus`：每个人按当时的理解填，最后一堆唯一值。

L38 结构手册里的「L0 方法论 / L1 零件 / L2 接口 / L3 框架 / L4 篇章 / L5 考场」
**是那一份文档的渲染选择，不是数据的属性**。同一批沙粒上可以并存
「按语法系统」和「按考试题型」两套分组，互不冲突——前提是层次不进存储。

**层次是查出来的，不是存出来的。**

## 2.6 最小 schema

```jsonc
// 观察：不可变
{ "id": "obs:L38:0109:permettre-fix",
  "lesson": "L38",
  "time": "01:09:00-01:09:30",
  "evidence": { "file": "...", "lines": "944-958" },
  "raw": "老师把 ils permettre les enfants à préparer 改成 aux enfants de se préparer" }

// 概念：廉价、可改
{ "id": "cpt:permettre-argument-frames",
  "kind": "grammar_rule",
  "label": "permettre 的论元框架",
  "tags": ["preposition_interface", "core", "B1"] }   // 来自受控词表

// 边：递归在 to 上（to 可以是观察，也可以是概念）
{ "from": "cpt:permettre-argument-frames",
  "to":   "obs:L38:0109:permettre-fix",
  "type": "observes",
  "authority": "teacher",              // §3
  "status": "confirmed",               // §3.3
  "reason": "老师另起一栏手写了三行论元框架" }
```

递归就在 `to` 上。整个模型三张表。

# 第 3 部分 · 权威模型

这是知识图谱项目最常死掉的地方，因此单列一部分。

## 3.1 观察层：只有老师有权

观察断言老师做了什么，权威是录音和他的纸面材料。不是 agent，也不是学习者。

这套规矩**已经在跑，并且已经拦下过东西**：

- ASR 三路分歧 → 不收 `en tout cas`
- 课上没讲 → 形容词性数配合表不出卡
- AI 批改独有的条目 → 不能升老师要求档
- 归属先行：`阅读8批改.pdf` 曾被证明是学生笔记而非老师批改

**冲突裁决**：观察之间冲突时比证据强度。已有先例——老师的讲义写 `dans mon temps libre`，
音频里念的是 `en`，纸面胜出。

## 3.2 概念层：使用者有权，但必须留痕

概念是「这些东西为我的目的应该放一起」，服务的是学习者，因此学习者说了算。

但正因为是判断，**必须记录谁提议、依据是什么**。

理由是可量化的：**963 条 provenance 里 201 条（20%）不是老师给的，是 agent 或
用户提议的**（`agent_supplement` 198 + `user_supplied` 3）。没有档位标记，
三个月后无法区分「老师说的」和「某个 agent 猜的」。

**这套东西已经存在于词的层面**：`补` 前缀 / `handout` 档 / 无后缀三档。
概念层照抄同一套。

## 3.3 三态：提议 / 确认 / 否决

| 状态 | 谁能置入 | 是否参与推理 |
|---|---|---|
| `proposed` | agent 可以自由提议 | **否** |
| `confirmed` | 使用者，或有老师证据支撑 | 是 |
| `rejected` | 使用者 | 否，但**保留在库中** |

**agent 可以提议，但只有 confirmed 的连接参与推理。**这样既不会没人建
（`genus` 那种「谁都能填、谁都不确认」的下场），也不会被 agent 的猜测污染。

## 3.4 否决是一等公民

回看 2026-08-24 至 08-26 这轮工作，**最有价值的动作几乎都是「不收」**：
丢掉 `en tout cas`、不给形容词表出卡、不合并 L34 的 `cadeau` 卡、不把 AI 批改升档。

一个「加链接容易、否决困难」的系统会不可逆地退化——加是单个动作，否决要论证。

因此：**被否决的连接必须留在库里并标记 `rejected` + 理由**，不能删除。

已有反例：L37 早就判定过疑问句练习卷「没有教学证据」，但那个判断只写在 inventory
的正文里，于是 2026-08-25 又被从头验证了一遍。

# 第 4 部分 · 不变式

以下每条都应可机器检查。

1. **观察不可变。**已发布的观察不得修改；纠正的办法是新增一条并标记取代关系。
2. **每个概念至少有一条 `observes` 边**，否则它是凭空创造的。
3. **`groups` 边构成的图无环。**
4. **对称边成对存在**（或存一条、查询时双向展开，二选一，全库一致）。
5. **每条边有 `authority` 和 `status`。**没有这两个字段的边不参与推理。
6. **`rejected` 的边不删除。**
7. **概念的 `tags` 只能取自 `tag-vocabulary.json`。**新增取值要改词表，不能自由填。
8. **证据文件必须是 UTF-8 可读文本**（沿用现有 provenance 契约）。
9. **身份层落地后，同一 canonical key 下的观察数 ≥ 1，且跨课时 ≥ 2。**

# 第 5 部分 · 迁移路径

分期，每期可独立停下，**都不破坏 8501**。

## 5.1 Phase 1 · 身份层（唯一的必要前提）

给 1,607 个 lemma 分配 canonical id，把 405 个跨课重复的归并。

- **产出**：lemma → canonical key 的映射表
- **不改**：`vocab.json` 的任何学习字段、manifest、SRS 进度
- **验收**：`un cadeau` 的 5 次出现指向同一个 key；全库跨课重复 lemma 数从 405 降到 0
- **成本**：机械为主，1,607 个字符串
- **退出条件**：映射表存在且可复算

**不做这一步，后面全部无效——任何图都建在沙子上。**

## 5.2 Phase 2 · 边

把 `teacher_action` 从行上提到边上，按 §2.3 建类型化的边。

- **验收**：§4 的不变式 1–8 全部可跑通；`groups` 无环
- **退出条件**：能回答「`aider qn à` 在哪几课出现、每次是什么关系」而不用字符串匹配

## 5.3 Phase 3 · 视图

在概念层上生成手册（介词接口、句型框架、题型打法）。

- **验收**：一份手册的每一条都能溯回到具体观察
- **注意**：视图是查询产物，不入库（§2.5）

## 5.4 Phase 4 · 补抽取（可选，可无限期推迟）

**20 节课有转录但无知识点**：L0–L8、L10–L20（L9 有）。约 30,000 行转录。
每课等价于一次完整 launch，是全部工作里成本最高的一块。

**建议顺序：放在最后。**在身份层落地之前补抽取，等于把 §1.2 的问题
按比例放大。而且这 20 节是较早的课，内容已被后续课程反复重教
（281 组跨课重复里相当一部分指向 L21/L22）。

# 第 6 部分 · 已知缺陷与风险

## 6.1 前一版聚类的可证缺陷

`听写/scripts/species_cluster_report.py`（2026-08-26）用 `french_items` 字符串重叠
连边。已收紧两次（只认拉丁字母项；边需共享 ≥2 项或 1 个全库 ≤4 次的罕见项），
结果从「10 课 28 点的巨簇」降到 54 个可读的簇。

**但仍有可证的坏合并**：那个「跨 7 课」的簇把两件不相干的事并在一起——
`-indre` 动词的拼写变位家族，和 `rencontrer / se retrouver / se connaître` 的
语义混淆。原因是某张卡同时列了 `se plaindre` 和 `se connaître`。

**第三条缺陷（2026-08-28 复核时发现）**：归一化函数
`normalize_item()` 会剥掉开头的冠词，于是 `french_items` 只列了裸冠词的知识点被
剥成空串、整条丢弃。实测丢了 3 条，**全部是代词/冠词类**：

| 课 | species | french_items |
|---|---|---|
| L22 | direct objects take le la or les | `['le','la','les']` |
| L26 | neutral le has no gender or number… | `['le']` |
| L26 | do not confuse predicative le with direct object le la | `['le','la','les']` |

要害不在少了 3 条，在于**这 3 条确实跨课重复（L22 ↔ L26），却被归一化规则
结构性地排除在跨课检测之外**。凡是身份就落在功能词上的知识点，这套工具永远看不见。
这不是参数问题，是「用证据字符串代替身份」的又一个必然后果。

**结论：那份聚类是候选清单，不是结论。**快照保留在
`VibeVoice/docs/french-wiki/census/analysis/`，README 里逐条写明了四个缺陷
（本节的第三条在 README 里编号为 4）。

## 6.2 标注计数不能当学习者数据

`teacher_corrected_error` 标的是「某节课发生了一次纠正」这个事件，由建卡时的
agent 施加，19 节有知识点的课之间没有统一标准。各课占比从 **0%（L9 0/98、L30 0/21）
到 69%（L28 9/13）**，L21 是 11%（8/73）。
同一个老师教同一个学生，这个方差更像标注习惯差异，不像错误率分布。
绝对数（L22 的 38 个）主要反映该课知识点总数（103 个）。

## 6.3 本设计可能重蹈覆辙的方式

| 风险 | 触发条件 | 防线 |
|---|---|---|
| canonical key 变成第二个 `genus` | key 允许自由填写 | key 必须来自受控生成规则或已有词表 |
| 概念层膨胀成无人维护的图 | 提议无成本、确认无人做 | §3.3 三态；只有 confirmed 参与推理 |
| 视图固化成存储 | 为了「方便」把层次存下来 | §2.5；不变式检查 |
| 图取代了产物 | 花力气建图，8501 反而没更新 | 每期验收都要求 8501 可用 |

# 第 7 部分 · 待审问题

审阅者请重点攻击这几条。

**7.1 沙粒粒度**：取 provenance 记录（963 条）是否正确？转录窗口（61,127 行）
更细但无语义；知识点（737）更粗但已经是解释。有没有第四种切法？

**7.2 canonical key 的命名规则**：怎么保证它不重蹈 `genus`？候选方案是「法语原形 +
消歧后缀」，但同形异义（`la location` 租赁 vs 地点）需要处理。

**7.3 存储位置**：独立文件，还是寄生在现有 `vocab.json` / species JSON 里？
独立更干净但引入同步问题；寄生不引入新文件但会把两个仓库耦合得更紧。

**7.4 概念层要不要进 8501**：它对学习者有直接价值（「这个点你在 L21 见过」），
还是只应服务于分析和手册？进 8501 意味着 UI 改动和新的测试面。

**7.5 权威模型是否过重**：三态 + authority + reason 对一个单人学习系统是否
过度设计？简化到两态（proposed/confirmed）够不够？

**7.6 有没有现成的东西可以直接用**：本设计接近 Topic Maps（ISO 13250）的
topic / occurrence / association 三件套，也接近 SKOS 的 concept scheme。
是否应该直接采用其中一个的序列化格式，而不是自定义？代价是什么？

**7.7 本设计是否值得做**：现有系统在单课范围内工作良好。跨课能力的收益
（手册、去重、复现分析）是否抵得上引入一整层的复杂度？如果不值得，
替代方案是「只按受控标签切片，永远不建身份层」——这条路能走多远？

**7.8 诊断落在 species，处方落在 lemma——这是不是一处错位？**
本文档举证身份失效，用的是 species（§1.2a：`genus` 642 个有值里 638 个唯一）；
举证跨课不可信，用的是 species 聚类翻车（§1.2c、§6.1 的跨 7 课坏合并）。
但 §5.1 Phase 1 做的是「给 1,607 个 **lemma** 分配 canonical id」，验收是
`un cadeau` 的 5 次出现指向同一个 key——全在 vocab 层。§5.2 搬 `teacher_action`
也在 vocab provenance 上。**737 个 species 的身份键，全篇没有分到任何一期。**

后果是可预测的：Phase 1 做完，`un cadeau` 归并了，而 §6.1 那个把 `-indre` 变位族
和 `se connaître` 并在一起的坏簇一点没动——那恰恰是本文档举证力度最大的失败现场。
§7.2 讨论 canonical key 命名时举的例子（`la location` 租赁 vs 地点）也是词，不是知识点。

三个可能的出路，请审阅者裁决：
（a）补一期 species 身份（Phase 1.5），验收写成可测的量，例如
「`genus` 唯一值率从 99.4% 降到某阈值以下」或「跨课簇的坏合并率低于 x」；
（b）承认第一期只治词层，那么 §1.2c 与 §6.1 就不能再当 Phase 1 的论据用，
§1.2 得改写成「词层与知识点层各有一套身份问题，本期只解词层」；
（c）反过来：先做 species 身份，词层的 405 个跨课重复其实已被 `补` 前缀部分缓解，
优先级可能反了。

# 附录 · 术语对照

| 本文档 | 标准名 | 备注 |
|---|---|---|
| 观察 / 沙粒 | occurrence、evidence record | Topic Maps 里叫 occurrence |
| 概念 / 节点 | topic、concept、entity | SKOS 里叫 concept |
| 概念抓观察 | 多对多归属 | 结构上是二分图；等价说法是超图（节点＝超边） |
| 概念抓概念 | 递归 / broader-narrower | SKOS `skos:broader`；Topic Maps association |
| 身份 | canonical entity、authority record | **当前系统缺的就是这个** |

**关于「知识图谱」这个词**：本设计确实属于知识图谱范畴，但主流知识图谱指
三元组（边是二元的）。本设计的节点一次可以罩住任意多个观察，那是**超边**。
这个区别决定了能否直接套用现成的三元组工具，因此不宜简单以「知识图谱」称之。
