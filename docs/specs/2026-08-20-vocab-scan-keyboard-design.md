# 速过改成键盘驱动（设计）

日期：2026-08-20
状态：设计已定，待实现
前置：`docs/specs/2026-08-13-vocab-scan-design.md`（速过 v1，已实现）
影响：`app.py`、`store.py`、`scan.py`；`scanaudio.py` 与 `mastery.py` 不动

---

## 1. 为什么改

速过 v1 上线后用户真扫了一课，结论是「还行，但点击不好使、播放也不好使」。实测量出根因：

| 目标 | 实际尺寸 |
|---|---|
| ▶ 播放 | **9 × 20 px** |
| 「不会」勾选框 | **13 × 13 px** |
| 盖住格（v1 里改过的） | 416 × 24 px |

行高 37px。鼠标操作的经验底线约 24px。**被抱怨的两个恰好是唯一没放大的两个**，改过的那个没被抱怨——诊断很干净。

音频本身没坏：静态服务返回 200、字节数一致，浏览器实测能加载（`canPlayType('audio/mp4a-latm')` 返回空串，但浏览器会嗅探容器，照放不误）。

但把按钮放大只是治标。真正的结论是：**过词这件事根本不该用鼠标**。它不需要输入文字，只需要「看一眼 → 表个态 → 下一个」，这正是键盘最擅长的。鼠标的成本不在点击本身，在**瞄准**；键盘没有瞄准成本。

## 2. 目标与非目标

**目标**：整个过词流程键盘完成，双手都能单独操作，手不离键盘。

**非目标**：

- 不做滚筒式放大（Dock 那种越靠中间越大）。留作第二步——键盘接管推进之后，滚筒只剩视觉价值，先跑几天再定值不值得。
- 不做鼠标拖拽标记。键盘方案成立后它降级成「触屏才需要」的备选，且要额外一份手感调试。
- 不碰数据模型。`rec_meaning` / `rec_produce` / `rec_audio` 三个方向、`words` 表不被自判污染的不变量，全部原样。

## 3. 键位

两只手完全对称，任何一只手累了都能换另一只继续。

| | 右手 | 左手 | 含义 | 入库 | 前进 |
|---|---|---|---|---|---|
| 揭晓 | `?` / `/` | `E` | 看答案 | ❌ | 不动 |
| 播放 | `空格` | `空格` | 出声，按几次响几次 | ❌ | 不动 |
| 会 | `←` | `A` | | ✅ | ✅ |
| 不会 | `→` | `D` | | ✅ | ✅ |
| 跳过 | `↓` | `S` | 不表态 | ❌ | ✅ |
| 回退 | `↑` | `W` | 改判 | ❌ | 回退 |

**上下是导航，左右是判定。** 表态即等于「这条看完了」，所以 ←/→ 自动前进，不必再按一次 ↓。

**`?` 要按 Shift**，所以 `/` 和 `?` 两个都绑，按哪个都认。另外 Firefox 里 `/` 是快速查找快捷键，必须 `preventDefault()`。

**焦点在任何表单控件上时全部让路**（`input` / `textarea` / `select` / `contentEditable`）。侧栏的选课、模式都是 combobox，方向键在它们身上是切换选项——不让路会串。

## 4. 发音规则

一句话概括：**发音属于题面就随便听，属于答案就得先揭晓。**

| 方向 | 发音是什么 | 切词时自动播 | 揭晓前按空格 |
|---|---|---|---|
| 听音→想双 | 题面（唯一题面） | ✅ 必须 | ✅ 可以 |
| 看法→想中 | 法语本就明码，不泄题 | ✅ 默认开，可关 | ✅ 可以 |
| 看中→想法 | **答案** | ❌ 永不 | ❌ 锁住 |

第三档正是 v1 里 `play_locked` 那道锁守的东西。空格必须遵守同一道锁，否则一响就把答案念了。锁住时不发声、不报错，当前行给一个静默的视觉提示（边框闪一下）。

## 5. 每次按键立刻入库

v1 是「攒一页，按钮提交」。改成**每次表态立刻写库**。实测支撑：

| | 实测 |
|---|---|
| 单条写库（含开关连接） | **0.36 ms** |
| `st.fragment` 往返一次 | **~85 ms** |
| 外层表格是否被重建 | **否** |

`st.fragment` 的 spike 验证过：fragment 内的按钮触发重跑时，外层 `st.markdown` 的时间戳不变、表格 DOM 节点保持同一个、挂在上面的自定义属性存活。所以写库不会把表格拆了重建，客户端的光标位置和揭晓状态都不受影响。

这样比攒批**更简单**：没有提交点、没有页边界语义、不需要 v1 那套 `data-rev` 清勾选的机制，中途关浏览器也一条不丢。分页从此只是「一屏显示几行」的显示问题，默认 20。

### 5.1 回传格式：累积操作列表

隐藏输入框携带**从进入本页起的全部操作**，逗号分隔，只增不改：

```
1201:1,1202:0,U:1202,1202:1,1203:0
```

- `<word_id>:1` = 会，`<word_id>:0` = 不会
- `U:<word_id>` = 撤销该词最近一条扫读记录（↑ 改判用）

服务端在 session_state 记 `scan_written`（已处理到第几条），每次 fragment 重跑只处理 `ops[scan_written:]`，然后更新计数。

fragment 里放三个东西，都用作用域 CSS 藏起来（见 §12）：

| 元素 | 作用 |
|---|---|
| `st.text_input(key="scan_sink")` | JS 往里写累积操作串 |
| `st.button(key="scan_flush")` | JS 写完立刻点它，触发 fragment 重跑 |
| 一个 `st.markdown` 回执 | 渲染当前的 `scan_written`，供 JS 确认写到哪了 |

写值必须走 React 的 native setter 再派发 `input` 事件（v1 的 S0 卡在真浏览器里验过这条通路），直接赋 `.value` React 看不见。

**为什么必须累积而不是单条**：一次往返 85ms，你连按两下时第二下会在服务端读走之前覆盖掉输入框的值——单条格式会**丢一次判定**。累积列表天然幂等，连按多快都不丢；Streamlit 若把多次重跑合并成一次，也只是一次把积压的都写掉，结果相同。

### 5.2 改判必须真的删

`mastery.mastery_score` 按天聚合时取的是**当天第一次**：

```python
if cur is None or dt < cur[1]:
    by_day[day] = (bool(ok), dt)   # 当天第一次为准
```

所以手滑按了 ←（会）之后再插一条 →（不会）**没有用**——这一天仍按第一条算。改判只能靠删。

新增 `store.delete_last_scan_attempt(word_id, skill)`，删除范围卡死：

- 只删 `attempts` 里该 `word_id` + 该 `skill` 的**最后一条**
- `skill` 必须在 `SCAN_SKILLS` 里
- `answer` 必须以 `（扫读·` 开头

三条同时满足才删。打字、念法语、变形练出来的历史碰不到。

## 6. 删掉鼠标那一套

## 7. 客户端状态

全部活在注入脚本里，不进 session_state：

| 状态 | 说明 |
|---|---|
| `cursor` | 当前是本页第几行 |
| `revealed` | 已揭晓的 word_id 集合，翻页清空 |
| `ops` | 累积操作列表，同步进隐藏输入框 |

当前行的视觉：整行底色高亮 + 自动 `scrollIntoView({block:'center'})`，让当前词始终在视野中间。表态后底色闪一下绿/红再前进——没有反馈你不知道那一下有没有生效。

走到本页最后一行再按 ↓ 或表态 → 自动翻页（一次完整 rerun，正常的）。翻页时 `revealed` 清空、`cursor` 归零、`ops` 重置、`scan_written` 归零。

**翻页必须等写库落定再发起。** 翻页是一次完整 rerun，会把表格连同注入脚本一起重建；如果此时最后一个词的判定还在 85ms 的往返路上，`ops` 会随着重建一起消失，那一条就丢了。所以顺序卡死：

1. JS 把最后一条 op 写进 sink、点 flush；
2. **等 fragment 的回执把 `scan_written` 涨到 `ops.length`**（轮询那个回执元素，超时 3 秒）；
3. 确认落定后才点翻页按钮。

回执等不到就不翻页，当前行给出提示——宁可停在这一页让人发现，也不能默默丢判定。

## 9. 错误处理与降级

| 情况 | 行为 |
|---|---|
| 键盘脚本没挂上（Streamlit 升级改了 DOM） | 页面显示不出当前行高亮 —— 这就是可见信号。播放按钮仍可点，但无法表态；需要人工介入，不做自动降级 |
| 发音还没预热完 | 当前行播放按钮置灰；空格不发声；扫读照常进行 |
| `say` 不可用 | 「听音→想双」入口禁用并说明；另两档正常 |
| 回传串有脏值 | `parse_ops` 静默丢弃该条，其余照常写 |
| `U:` 指向的词没有可删记录 | `delete_last_scan_attempt` 返回 0，静默 |
| 某词没有中文释义 | 显示「（无释义）」，仍可表态 |

## 11. 分两步

**第一步（本设计）**：键盘操作 + 当前行高亮 + 自动滚到中间 + 大播放按钮，在现有表格上做，删掉鼠标那一套。

**第二步（未定）**：滚筒式放大（Dock 效果）。键盘接管推进之后它只剩视觉价值，先用几天再定。真做的话数据层与键盘层都不用动，只换渲染。

## 12. 未决

- 自动播放在「看法→想中」档默认开，但没有实测过是帮忙还是吵。用几天再定要不要改默认。
- sink 输入框、flush 按钮、回执三个元素都用一小段作用域 CSS（`.st-key-scan_sink`、`.st-key-scan_flush` 等）藏掉。这是 `AGENTS.md` 里点名要慎重的全局 CSS，但不带 `!important`、只命中一个 key 类。若实现时发现有更干净的原生做法，优先用原生。
- 键盘脚本挂不上时没有自动降级路径。鼠标那套删掉之后，脚本失效等于整个速过不可用。可接受，因为 v1 的 S0 已经验证过同一套注入手法稳定，且失效是立刻可见的。
